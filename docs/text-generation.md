# Text generation

## Abstract

**Text generation** runs the trained causal LM **one token at a time**: forward the prefix, read logits for the last position, pick the next byte (greedy argmax or **temperature**-scaled sampling), append, repeat until length or stop. The `./ann lm` command exposes generate mode for the toy stack.

## What problem it solves (plain language)

Training optimizes next-token probabilities; **using** the model means chaining those predictions into continuations. Generation must mirror training’s **causal** visibility ([causal-attention.md](causal-attention.md))—each new byte only sees the past—and turn logits into a discrete choice.

## How it works for a human (intuition, analogy)

Autocomplete on a phone: you type a prefix, the model suggests the most likely next character, you accept it, and the prefix grows. **Greedy** mode always picks the single best byte. **Temperature** widens or narrows the lottery—hotter = more random, colder ≈ argmax.

## Formal view (definitions, formulas, shapes, algorithms)

**State.** Prefix token ids \(x_{0:n-1}\), length \(n \le\) `LM_MAX_CTX`.

**One step.**

1. Build `T × 32` embeddings + pos enc; run `LM_N_BLOCKS` [transformer blocks](transformer-blocks.md) with `causal = 1`.
2. Last hidden row \(h_{n-1} \in \mathbb{R}^{32}\).
3. Logits \(\mathbf{z} = h_{n-1} W_{\text{head}} + b \in \mathbb{R}^{256}\).

**Greedy:**

\[
x_n = \arg\max_k z_k
\]

**Temperature** \(\tau > 0\):

\[
p_k = \frac{\exp(z_k / \tau)}{\sum_j \exp(z_j / \tau)},\quad x_n \sim \mathrm{Categorical}(\mathbf{p})
\]

\(\tau \to 0^+\) approaches argmax; \(\tau = 1\) is standard softmax sampling.

**Loop (`lm_generate`).**

```text
ids = tokenize(prompt)
repeat up to max_new_tokens:
  if len(ids) >= LM_MAX_CTX: break
  lm_forward(ids) -> H
  z = lm_head_logits(H, last_row)
  next = greedy(z) OR sample_temperature(z, tau)
  append next to ids
decode ids to bytes / print
```

**KV-cache (optional).** Recompute only the new row’s attention keys/values; full \(T×T\) scores each step are correct but \(O(T^2)\) per token—acceptable for `T ≤ 32`.

## Complexity / numerical pitfalls / design choices (CS depth)

**Per new token.** One forward over length \(n\): \(O(n)\) layers each with \(O(n^2 d)\) attention → **\(O(L n^2 d)\)** naive, \(L =\) `LM_N_BLOCKS`. For fixed small ctx, linear in number of generated bytes.

**Greedy vs sample.** Greedy loops on repeated tokens; sampling adds diversity but needs tuned \(\tau\).

**Byte-level artifacts.** `LM_BYTE_VOCAB` emits raw bytes—UTF-8 multibyte characters may split; acceptable for a C toy.

**Numerical.** Temperature divides logits; very large \(\tau\) → uniform noise; very small \(\tau\) → overflow in `exp` if logits are huge—reuse stable softmax ([softmax.md](softmax.md)).

**Stop criteria.** End on max length, user byte (e.g. `\n`), or when EOS id is defined (optional in vocab).

## How it shows up in this repo

- [`lang/lm.h`](../lang/lm.h): `lm_generate(lm, prompt, max_tokens, tau, out_buf)`.
  - `tau <= 0` or `tau == 1.0 && greedy_flag` → argmax via `lm_sample_greedy`.
  - `tau > 0` → `lm_sample_temperature`.
- [`lang/tokenize.h`](../lang/tokenize.h): prompt → byte ids.
- CLI: `./ann lm generate "hello "` (planned flags: `--max-tokens`, `--temperature`).
- Build: `make` links `lang/lm.c`, blocks, attn, embed; run from repo root.

## Tiny worked example

Prompt `"h"` → id `[104]`. After overfitting training on `"hello"`, greedy might produce:

| step | prefix | last-byte logit winner |
|------|--------|-------------------------|
| 0 | `h` | `e` (101) |
| 1 | `he` | `l` (108) |
| 2 | `hel` | `l` |
| 3 | `hell` | `o` (111) |

With `LM_MAX_CTX = 32`, at most 31 extensions after a 1-byte prompt. Temperature \(\tau = 0.8\) slightly flattens logits so occasional non-argmax bytes appear if training is imperfect.
